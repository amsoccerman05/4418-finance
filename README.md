# 4418 Finance V1 — local schema review

Purchase-order approval and school-submission tracking. The school's Google Sheet remains the authoritative document. No spreadsheet API, line-item form, budgeting, accounting, receipts, Inventory operations or notifications are included.

## Local setup

1. `npm ci`
2. Copy `.env.example` to git-ignored `.env.local`; use the existing project's **public anon/publishable key**, never a service-role key. No production migration has been applied by this project.
3. `npm run dev` after the schema is reviewed/applied. `npm test` uses a local PostgreSQL engine and intercepted browser fixtures; it never writes production data.
4. `npm run build` runs TypeScript and builds the app. UI screenshots are generated by tests at 390px and 1440px.

Start review with [docs/SCHEMA-REVIEW.md](docs/SCHEMA-REVIEW.md).

## Repository layout

- `src/service.ts`: Supabase repository, models, URL validation and queue helpers; no privileged key.
- `src/main.tsx`: overview, request editor, approval detail and assignment management.
- `src/suite-auth.ts`: existing suite broker adapter with Finance added to the exact-origin list.
- `src/suite-colors.css`, `src/tokens.css`: suite colors and design tokens reused from Hub.
- `supabase/migrations/202609120002_finance_v1.sql`: review-only Finance migration.
- `tests/database.spec.ts`: actual local SQL/RLS/permission tests.
- `tests/ui.spec.ts`: responsive student/approver workflows with intercepted APIs.
- `tests/sso.spec.ts`: real cross-origin browser messaging with the Hub broker source snapshot and mocked Supabase Auth. No fabricated production credentials.

## Release steps — do not deploy before schema review

1. Review the migration and policy decisions in `docs/SCHEMA-REVIEW.md`. Inspect the existing `public.areas` names and `team_attendance_members` registration records; Finance does not insert or change either.
2. After approval, an owner runs **only** `202609120002_finance_v1.sql` once in the existing project's SQL Editor. Do not rerun an earlier Inventory/Pit/Attendance migration.
3. Review and deploy the one-line local Hub change in `4418-team-hub/src/suite-auth.ts`: add exactly `https://finance.frc4418.org`. This is required before production Finance SSO can work. No other suite repo needs modification.
4. Create a GitHub repository `4418-finance`, push this local repository, and choose Settings → Pages → GitHub Actions. Set repository variables `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY` to the existing shared public configuration.
5. Add `https://finance.frc4418.org/` and `https://finance.frc4418.org/?password-reset=1` to Supabase Auth redirect allowlist. Preserve all existing URLs.
6. When ready for the new domain, manually add **only** `CNAME finance → amsoccerman05.github.io`. `public/CNAME` already specifies `finance.frc4418.org`. Configure the Pages custom domain and enable HTTPS when its certificate is ready. No DNS was changed during this build.
7. Manually run **Review and deploy Finance**, confirming `schema_reviewed_and_applied`. Push alone does not deploy. The workflow builds/tests, validates public configuration, and publishes Pages only after that explicit gate.
8. An existing active mentor/admin signs in and opens **Finance assignments**. Assign separate people to `finance_approver` and `po_approver`, plus a `school_submitter`. Assignment changes require explanations and are audited. Registered students can then submit their sheets.

No GitHub remote repository, production schema, deployment or DNS was created/changed during this local build.
